# Starting a new package

- Location: a new package's source lives in `source/` at the project root with `source/skill-package.json` as its manifest; a further package takes its own folder under `source/` with the same shape, so a later session finds every package without asking. An existing package stays where it is.
- Before its first file: if no project instruction keeps its current state for a later session, ask once whether the project will keep the recommended maintenance documents, its own, or none, since a later session recovers the build root, delivery route, and open questions only from what the project records. Only when the user chooses the recommended ones, or later asks for them, set them up with `references/maintenance-docs.md`; then the project's own instructions own them.
- Then tell the user how the work runs from here, in their language, so they can follow it without knowing Skill Rails. The four points and their order are fixed, the words are free: the skill is designed and refined as source in `source/` for as long as they like, and nothing is built meanwhile; when they ask for a build or a test, the source is built into a standalone skill folder, each file placed where its declarations put it and each declared tool shipped with it; the delivery route is chosen with them before the first build, and a test builds, carries that route out on this machine, and has a fresh AI use the result; from then on changes are made in the source, and rebuilt, tested, or delivered when they ask.
