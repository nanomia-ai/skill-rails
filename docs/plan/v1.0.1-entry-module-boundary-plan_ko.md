# Skill Rails v1.0.1 entry·module 경계 보완 계획

문서 상태: 구현·검증·release 완료 — 판단은 `../reviews/v1.0.1_ko.md`
작성일: 2026-09-15 KST
대상 버전: root와 authoring package `1.0.1`

## 목적

v1.0.0이 이미 제공하는 entry와 whole-file module 구조를 바꾸지 않고, 처음 보는 저작 AI가 공통 맥락과 조건부 맥락을 잘못 분리할 가능성을 줄인다.

Entry는 모든 실행에 필요한 최소이면서 완전한 계약이어야 한다. 실제 작업이 어떤 내용을 의미 손실 없이 건너뛸 수 있고, 그 읽기 절감이 탐색과 재읽기 비용보다 클 때만 별도 module로 분리한다.

## 변경 범위

- Entry에 모든 분기를 해석하는 데 필요한 핵심 배경·의도, 목적, 사용 trigger, 운영 경계, 공통 규칙, 현재 입력, 완료 evidence와 optional module의 정확한 read condition을 함께 둔다.
- Optional module의 read condition은 그 module을 열기 전에 현재 작업과 선언된 입력으로 판정할 수 있어야 한다.
- 여러 target이 공유하는 같은 규칙은 canonical module owner 하나가 소유하고 각 consuming entry가 읽기 조건을 밝힌다.
- 함께 판단해야 하는 의미는 길이나 heading이 다르더라도 분리하지 않는다.
- 생성 대상 목록에 imported module을 명시한다.
- Renderer/core에는 deterministic formatting과 mechanically decidable safety check만 두고 semantic safety와 permission judgment는 domain source, AI 또는 user에 남긴다.
- Inspect에서 선언 관계가 없으면 gap을 명시하고, 관찰된 유지보수 실패가 필요성을 보일 때만 canonical owner에 관계를 추가한다.

## 범위 밖

- 자동 semantic splitter
- 2차·3차 nested module graph
- 새 router, schema, runtime mode 또는 검증 matrix
- 문서 길이와 heading 수를 기준으로 한 자동 분할
- v1.0.0 review의 소급 변경

## 완료 조건

1. Canonical authoring entry와 generated entry에 같은 의미가 전달된다.
2. Existing source graph, whole-file materialization, standalone build와 currentness 계약이 바뀌지 않는다.
3. 독립 검토자 한 명이 문구와 인접한 실제 오동작 위험만 bounded하게 교차 검토한다.
4. Targeted build test와 default verification이 통과한다.
5. 구조 검사를 cold-AI 행동 개선이나 token 절감의 증거로 올리지 않는다.

## Release gate

구현과 기계 검증은 `../implementation-verification_ko.md`가 소유하고, 계획과 달라진 선택·재검토 조건은 `implementation-evolution-plan_ko.md`의 E-038이 소유한다. 사용자 승인 뒤 commit, annotated tag, push와 두 host 재설치를 완료했다.

릴리스 완료와 최종 수용 판단은 `../reviews/v1.0.1_ko.md`에 기록했다.
