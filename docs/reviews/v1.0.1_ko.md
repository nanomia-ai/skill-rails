# Skill Rails v1.0.1 리뷰

문서 상태: 완료 버전의 판단 기록
검토일: 2026-09-15 KST
대상 버전: root package와 authoring package `1.0.1`

## 결론

Skill Rails v1.0.1은 **entry와 optional module의 의미 경계를 더 명확하게 닫은 사용 가능 patch**로 채택한다. Source graph, runtime mode, schema와 설치 구조는 바꾸지 않았으며, v1.0.0의 단순한 저작 모델 위에 새 기계 장치를 추가하지 않았다.

이번 버전이 고친 것은 “entry를 짧게 하라”는 표현이 저작 AI에게 의미 축약으로 읽힐 수 있던 전달 결함이다. Entry는 이제 모든 분기를 해석하는 데 필요한 핵심 배경·의도, 목적, 사용 trigger, 운영 경계, 공통 규칙 또는 shared owner pointer, 현재 입력과 완료 evidence를 갖춘 최소 완전 always-read contract다. Optional module은 해당 내용을 실제 작업이 안전하게 건너뛸 수 있고 읽기 절감이 탐색·재읽기 비용보다 클 때만 만들며, read condition은 module을 열기 전에 현재 작업과 선언된 입력으로 판정할 수 있어야 한다.

## 검토와 전달 증거

- 초기 Codex 계열 검토가 imported module 누락과 넓은 `safety work` 표현을 찾았다.
- 기존 Claude Fable 5 세션의 두 차례 bounded 읽기 전용 반증 검토는 전체 entry와 최종 문구를 각각 PASS로 판정했다. 마지막 검토는 수정 필요 0건이었다.
- Release commit은 `c4cbaa540663862211ab7690fd359e2dce309ee3`이고 annotated tag `v1.0.1`의 peeled commit도 같다.
- `npm run verify`는 31/31 통과했다. Generated target은 36 files/203,518B, tree `1268cac2b5532d8f5a8d191d2734e4cb921e3a5135ddc7d4827ebdc94ce3aae1`로 artifact-intact/source-current다.
- `skills@1.5.26`의 정상 repository 경로로 global `skill-rails`을 Codex와 Claude Code에 설치했다. 두 host의 installed `check`가 package/core `1.0.1`, 같은 tree와 artifact-intact를 반환했다.

정확한 구현·설치 증거와 `unproven` 경계는 `../implementation-verification_ko.md`가 소유한다. 이 리뷰는 그 범위를 확장하지 않는다.

## 남은 한계와 재개 조건

새 문구가 실제 cold AI의 분할 판단과 token 비용을 얼마나 개선하는지는 아직 `unproven`이다. 이를 닫기 위한 synthetic matrix나 자동 semantic splitter는 만들지 않는다.

첫 실제 Devflow target에서 다음 중 하나가 관찰될 때만 이 경계를 다시 연다.

- 모든 분기에 필요한 배경·의도·운영 경계가 entry에서 누락된다.
- optional module의 조건을 판단하려고 그 module을 먼저 읽어야 한다.
- 항상 읽지 않아도 되는 module을 매번 읽는다.
- 함께 판단해야 할 의미가 여러 파일로 갈라져 오판이나 반복 탐색을 만든다.
- shared rule이 여러 target에 복사되어 owner가 다시 분산된다.

이때 먼저 authoring 문구와 실제 target의 source boundary를 확인하며, 곧바로 새 schema·runtime·router 문제로 확대하지 않는다.
