# Work stage

Use this reference when the generated entry maps the `work` token here. Ordinary prose work does not require the verifier Decision.

## Purpose

Continue the requested prose work from the task's durable state. The verifier lane is not a prerequisite for reading, explaining, or updating prose that the user placed in scope.

## Shared rules

- Interpret task state with the [Status notation judgment core](canon.md#status-notation-judgment-core).
- If a dispatched attempt fails because its guidance was insufficient, use the [Failure ladder](canon.md#failure-ladder). Do not count ordinary correction or review recurrence as another ladder attempt.
- Report evidence with the [Evidence credit notation](canon.md#evidence-credit-notation).

## Working boundary

Read the named task and its progress log before changing prose. Preserve card identity and existing user bytes. A status suffix is evidence about task state; a journal entry or remembered claim is not.

When the requested work is read-only, return the requested explanation with its source and uncertainty. When the request authorizes an edit, change only the named prose owner and verify the local links or format that the edit can affect.

## Handoff

Name the exact artifact read or changed, the evidence observed, and the next action. Do not report verifier completion merely because the verification lane is unavailable or deferred.
